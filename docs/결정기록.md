## 2026-11-18 · #3 로그인 구현에서 고른 것
- 세션 갱신은 `proxy.ts` 가 아니라 `middleware.ts`(Edge 런타임). Next 16 의 `proxy.ts` 는 Node 런타임 전용인데 OpenNext Cloudflare 1.20 은 Node 미들웨어를 "실험, 공식 유지 안 함"으로만 지원한다. Next 가 이름이 바뀌었다는 경고만 내고 그대로 동작한다. OpenNext 가 Node 미들웨어를 정식 지원하면 옮긴다. (내 판단)
- 로그인 쿠키가 없는 요청은 미들웨어가 바로 넘긴다. 손님(대부분의 방문)마다 Auth 서버를 부르지 않게. (내 판단)
- Turnstile 은 보이지 않는 위젯(Invisible)으로, 첫 픽 직전에만 스크립트를 받는다. 구경만 하는 사람의 첫 화면을 무겁게 하지 않는다. (내 판단, 위젯 종류는 사용자에게 안내)
- 이미 가입된 구글 계정의 픽 옮기기는 설계대로 Edge Function(`merge-anon`) + DB 함수. 앱 서버(Workers)에 service_role 키를 두지 않으려고 Next 라우트로 옮기지 않았다. (내 판단)
- `merge-anon` 허용 출처 비밀값 등록은 자동 분류기가 막아서 사용자가 대시보드에서 넣는다.

- **봇 계정 정리**: 탈퇴는 지난 픽을 남기지만, 운영자가 봇으로 판단한 계정은 계정을 지우기 전에 `purge_bot_picks`로 픽을 지운다. 결과가 확정된 라운드의 픽은 순위 기록과 어긋나지 않게 남긴다. 관리자 화면 버튼은 #6. 버린 안: 탈퇴와 똑같이 남기기(봇 표가 순위에 남음), 확정 라운드까지 지우기(결과 기록과 표 수가 어긋남).
- **등록 직후 공유 띠**: 등록하면 상세(`?new=1`)에 "등록했어요 + 링크 나누기" 띠를 띄운다. 첫 픽은 보통 아는 사람에게서 와서 그 순간에 공유를 권한다. 토스트는 금방 사라져서 띠로 바꿨다.
- **앱 안 브라우저 안내**: 로그인 전이면 등록 화면 위에 먼저 알린다. 카톡·안드로이드는 기본 브라우저로 바로 열고, 아이폰의 다른 앱은 "··· → Safari로 열기"를 안내한다(웹에서 열 길이 없음).
- **탈퇴 전 최근 로그인 확인**: 10분 안에 로그인한 세션만 탈퇴할 수 있다(토큰 `amr` 시각, 함수에서도 검사). 아니면 구글 계정 고르기를 한 번 더 거친다. 휴대폰을 남이 잠깐 쓰는 사이 탈퇴되는 일을 막는다. 대가: 탈퇴가 한 단계 길어진다.
- **(같은 날 뒤집음) 등록 화면의 앱 안 브라우저 안내는 뺀다**(사용자 결정). 손님은 "연습생 등록하기"를 누르면 등록 화면이 아니라 로그인 창으로 가고, 그 창이 이미 앱 안 브라우저를 처리한다. 안내는 `/register` 주소를 직접 열 때만 보이는데 홍보에 그 주소를 쓰지 않는다. 기본 브라우저로 여는 `openExternal` 은 로그인 창이 그대로 쓴다.
- **로그인하고 돌아오면 바로 등록**(사용자 요청, 2026-11-18). 손님이 폼을 다 쓰고 "등록하기"를 누르면 로그인 시트가 뜨고, 로그인 뒤 등록 화면으로 돌아와 쓴 내용으로 한 번 바로 등록한다. 전에는 내용은 남아 있어도 다시 눌러야 했다. 시트 문구도 "로그인하면 바로 등록돼요"로 바꿨다(로그인 기록에서는 계속 `register`로 센다).
- **공유·홍보 주소는 글 상세와 메인만**(사용자 결정, 2026-11-18). 인스타·카톡에 올라가는 주소는 내 연습생 상세(공유하기)나 메인이고 `/register`는 쓰지 않는다. 지금 코드도 그렇다(공유하기는 상세 주소만 만든다).

## 2026-11-18 · #5 이름 검색·조회수에서 고른 것
- **조회수는 Vault 토큰으로 서버만 올린다.** Workers 에 service_role 키를 두지 않는다는 #3 결정을 지키면서도 브라우저가 조회수를 부풀리지 못하게, Vault 의 `view_token` 과 같은 값을 Worker 비밀값으로 둔 서버만 `count_view` 를 부를 수 있게 했다. 버린 안: SNS 기록(`record_sns`)처럼 손님 키를 믿기(스크립트로 끝없이 늘릴 수 있음), Workers 에 service_role 키 두기(새는 순간 모든 표가 위험). (내 판단)
- **손님 조회는 IP 하루 한 번.** 쿠키 기준이면 첫 방문 서버 렌더에 쿠키가 없고, 쿠키를 지우면 계속 늘어난다. 같은 와이파이의 여러 사람이 하나로 세지는 것은 조회수가 참고용이라 감수한다(기획서 4절). (내 판단)
- **검색은 GET 폼.** 스크립트가 늦게 받아져도 바로 찾을 수 있고, 검색 결과를 링크로 나눌 수 있다("우리 애 찾아서 픽해 줘"). 결과 개수는 첫 24개까지만 알아서 보여 주지 않는다. (내 판단)

## 2026-11-18 · #6 댓글·신고·관리자에서 고른 것
- **금지어는 DB 한 곳에서 거른다.** 화면에 같은 목록을 또 두면 둘이 어긋난다. 걸려도 글은 입력칸에 남겨 고쳐 보낼 수 있게 했다(기획서 "보내기 전에 안내"). 버린 안: 화면에서 먼저 거르기(목록이 두 군데), 외부 욕설 필터 API(1차엔 과함). (내 판단)
- **신고 사유는 고르게 하지 않는다.** 관리자가 대상을 직접 보고 판단하고, 고르는 단계가 늘면 신고가 줄어든다. 대신 시트 본문에 "동물이 아닌 사진·불쾌한 사진·남의 사진" 같은 예를 적었다. (내 판단)
- **손님이 쓴 댓글은 로그인 뒤 바로 올린다.** 로그인 시트 문구가 이미 "로그인하면 바로 올라가요"라고 약속하고, 등록 이어하기(#5)와 같은 경험으로 맞췄다. (내 판단)
- **관리자 화면은 관리자가 아니면 404.** 있다는 것도 알리지 않는다. 진짜 권한은 DB 함수와 Edge Function 이 다시 확인한다. (내 판단)
- **안 읽은 알림 점은 잉크색.** 분홍은 픽 관련에만 쓰는 색 규칙을 지켰다. (내 판단)
- **라운드 결과 다시 계산은 #7 로 미룬다.** 결과 확정 함수가 #7 에서 생기므로, 그 함수를 다시 부르는 버튼도 그때 관리자 화면에 붙인다.
