## 0. 한눈에

| 층 | 고른 것 |
|---|---|
| 화면 | Next.js(App Router) + TypeScript, CSS Modules + `tokens.css`, PWA(직접 쓴 manifest·service worker) |
| 배포 | Cloudflare Workers (`@opennextjs/cloudflare`) |
| 데이터·로그인·사진 | Supabase: Postgres, Auth(구글 + 익명 로그인), Storage, pg_cron·pg_net, Edge Functions |
| 규칙 | Postgres 함수(RPC) 한 곳: 픽·등록·댓글 한도, 라운드 마감·결과 확정 |
| 메일 / 푸시 | Gmail SMTP / Web Push(VAPID), 둘 다 Supabase Edge Function에서 보냄 |
| 봇 막기 | Cloudflare Turnstile (익명 로그인·등록에) |
| 시험 | Vitest(일정 계산 같은 순수 함수), pgTAP(`supabase test db`, 픽 한도), Playwright(주요 흐름) |

**플랫폼**: 웹(데스크톱·모바일 브라우저) + PWA(홈 화면 설치, 웹 푸시). iOS·Android 네이티브 앱은 1차 범위 밖(기획서 "나중"). PWA로 설치·푸시가 되고, 앱 스토어가 필요해지면 PWA를 감싸서 낸다. 아이폰 웹 푸시는 홈 화면 설치(iOS 16.4+)가 필요해서 메일·알림함을 기본 전달로 둔다.

### 1-3. 데이터·로그인·사진 저장

| 후보 | 장점 | 단점 | 결정 | 이유 |
|---|---|---|---|---|
| Supabase | Postgres(유일 제약·트랜잭션·잠금으로 픽 한도를 정확히), 구글 로그인, **익명 로그인 → 구글 계정 연결**(같은 사용자 번호 유지), Storage, pg_cron, 행 단위 권한(RLS) | 프로젝트 하나 늘 때마다 컴퓨트 요금(Micro 약 $10/월)이 붙음(안 쓰던 pleamarket을 지워 상쇄) | ✅ | 기획의 "비로그인 1픽 → 로그인하면 이어짐"을 익명 로그인 + `linkIdentity`가 그대로 해 줌. 연결된 Supabase MCP로 운영도 편함. 이미 쓰는 **Pro 조직**(Haul project)에 넣어서 일시정지 없음, 매일 백업(7일), 월 활성 사용자 10만·Storage 100GB·전송량 250GB까지 포함(9절) |
| Firebase | 익명 로그인·푸시(FCM) 강함 | 문서형 DB라 "하루 3픽·같은 글 하루 1번" 같은 집계 규칙을 트랜잭션으로 짜기 번거로움, 순위 정렬 비용 | ❌ | 규칙이 집계 중심이라 SQL이 맞음 |
| Cloudflare D1 + R2 + 직접 만든 로그인 | 한 회사로 통일 | 로그인·익명 연결·예약 작업을 직접 만들어야 함 | ❌ | 만들 것이 너무 많음 |

### 1-4. 규칙을 어디서 지키나 (아키텍처 선택은 2절)
픽 한도·등록 한도·라운드 마감은 **Postgres 함수 한 곳**에서 지킨다. 화면이나 Next.js 서버에서도 미리 막지만(빠른 안내용), 최종 판단은 DB 함수다.

### 1-6. 메일·푸시

| 스펙 | 후보 | 결정 | 이유 |
|---|---|---|---|
| 1위 메일 | **Gmail SMTP** ✅ / Resend ❌ / AWS SES ❌ / Supabase SMTP ❌ | Gmail SMTP | 보내는 주소를 운영자 Gmail로 하려고(2026-11-19 사용자 결정, #7). Edge Function은 25·587을 막아 465(SSL)로 보내고(`nodemailer`), 하루 500통이면 라운드마다 1·2위 주인에게 넉넉함. Resend는 처음 고른 안이었으나 gmail.com 주소로는 보낼 수 없어(도메인 인증 필요) 바꿈. 도메인을 사면 다시 볼 수 있다. SES는 설정이 무겁고 Supabase SMTP는 인증 메일용 |
| 웹 푸시 | **표준 Web Push(VAPID)** ✅ / FCM ❌ / OneSignal ❌ | VAPID | 별도 회사 없이 브라우저 표준. 보내는 쪽은 Edge Function(Deno)에서 웹 푸시 라이브러리 사용. FCM·OneSignal은 SDK·추적 코드가 붙음 |

### 1-9. PWA

| 후보 | 결정 | 이유 |
|---|---|---|
| 직접 쓴 `manifest.webmanifest` + 작은 `sw.js`(푸시 받기, 오프라인 안내 화면만) | ✅ | 필요한 건 설치·푸시·오프라인 안내뿐. 캐시 전략 라이브러리는 과함 |

**만든 것(#8)**
- manifest: `app/manifest.ts`(Next 가 `/manifest.webmanifest` 로 낸다). 이름 "프로듀스 댕냥", 짧은 이름 "댕냥", `standalone`. 아이콘은 `public/icons/`(192·512·마스크용 512)와 `app/apple-icon.png`(180). 탭 아이콘은 `app/favicon.ico`(16·32·48, "댕냥"만 넣은 작은 판 `icon.html#small`). 아이콘 원본은 `scripts/icons/icon.html`, 다시 만들 때 `scripts/icons/make.sh`(크롬 머리 없는 모드로 512 만 찍고 작은 크기는 sips·ffmpeg 로 줄인다. 크롬은 창을 약 500px 아래로 줄이지 못해 작은 크기를 바로 찍으면 잘린다. favicon 안 PNG 는 RGBA 여야 Next 빌드가 읽는다, #35).
- 서비스 워커 `public/sw.js`: 모든 화면에서 `features/pwa/RegisterSW`가 화면이 다 뜬 뒤 등록한다. 설치 때 `/offline.html`만 캐시(`pd-offline-v2`)에 담고(운영은 이 주소를 `/offline`으로 넘기므로 받은 본문으로 새 응답을 만들어 담는다), 페이지 이동 요청만 네트워크로 받다가 실패하면 그 안내 화면을 준다. 사진·API·스크립트는 건드리지 않는다(표 수가 늘 최신이어야 해서). 안내 화면을 고치면 캐시 이름 숫자를 올린다.
- 아이폰·아이패드는 이제 "홈 화면에 추가"하면 앱으로 열리므로 알림 받기 칸이 설치 안내를 보여 준다(4-4).

### 1-9-1. 공유 미리보기(#8)

| 후보 | 결정 | 이유 |
|---|---|---|
| Next `opengraph-image.tsx` + `next/og`(satori·resvg) | ✅ | 글마다 사진·이름이 든 그림을 요청 때 그린다. Next 가 `og:image`·크기를 알아서 넣는다 |
| 대표 사진 원본을 그대로 `og:image` | ❌ | "우리 애 픽해 주세요"·게시판 이름이 안 들어가고, 세로 사진이 메신저에서 잘린다 |
| 글을 올릴 때 미리 그려 저장소에 두기 | ❌ | 이름·사진을 바꾸면 다시 그려야 하고, 올리기 흐름이 무거워진다 |

- 글: `app/[board]/[id]/opengraph-image.tsx` → `features/share/og.tsx`. 왼쪽 대표 사진(504×630), 오른쪽 제호·게시판·이름·"우리 애 픽해 주세요". 숨김·삭제·없는 글은 사이트 그림. 사이트(`app/opengraph-image.tsx`)·명예의 전당(`app/hall/opengraph-image.tsx`)은 흰 종이 바탕에 분홍 제호(분홍 바탕은 "분홍은 누르는 곳에만" 규칙과 맞지 않아 바꿈).
- 사진은 서버가 받아 data 주소로 넣는다. `next/og` 가 WebP 를 그리지 못해 Supabase 이미지 변환(`/render/image`, 웹P를 받지 않는다고 알리면 JPEG)으로 받고, 변환이 없는 로컬에서는 원본이 JPEG·PNG 일 때만 쓴다. 못 받으면 분홍 판.
- 한글 글꼴은 그림에 쓰는 글자만 Google Fonts 에서 TTF 로 받는다(`text=`). 못 받으면 글자 없이 그린다.
- 절대 주소는 `metadataBase`(`NEXT_PUBLIC_SITE_URL`, 배포 때 넣는다).
- 사이트 푸터·약관의 문의 메일은 `NEXT_PUBLIC_CONTACT_EMAIL`(#16). 공개 저장소라 실제 주소는 배포 명령에서만 넣는다.
- 무게: 그림 엔진(wasm)이 워커에 들어가 압축 크기가 1,542KiB → 2,378KiB 가 됐다(Cloudflare 무료 한도 3,072KiB). 큰 의존성을 더할 때는 `wrangler deploy --dry-run` 으로 먼저 잰다.

## 2. 아키텍처

| 후보 | 장점 | 단점 | 결정 | 이유 |
|---|---|---|---|---|
| **A. 기능 단위 폴더 + 규칙은 DB 함수(RPC)** | 한도 검사가 잠금과 함께 한 곳에서 원자적, 화면은 RPC만 부름, RLS로 직접 쓰기 차단 | SQL 함수를 잘 시험해야 함(pgTAP) | ✅ | 이 서비스의 핵심 위험은 "표가 새는 것". 동시에 두 번 눌러도 4표가 되면 안 됨 → DB 잠금이 가장 단단함 |
| B. 규칙을 Next.js 서버 액션에 두고 DB는 저장만 | TypeScript로 다 씀 | 검사와 저장 사이 경쟁 상태, 같은 검사가 여러 곳에 생김 | ❌ | |
| C. 별도 API 서버(Express 등) | 자유도 | 서버 하나 더 운영 | ❌ | 혼자 유지보수하기에 부담 |

화면 쪽 구조: **기능(feature) 폴더**가 기본(`picks`, `entries`, `rounds`, `featured`, `comments`, `auth`, `notifications`, `admin`), 공통 부품은 `shared/ui`, 공통 함수는 `shared/lib`. 폴더 트리는 [구현도](구현도.md) 3절.

### 구조 규칙

keel 하네스(#37, 2026-11-24)에서 위 결정을 코드 규칙으로 옮긴 것. 규칙마다 무엇이 막는지는 [RULES.md](RULES.md).

| ID | 규칙 | 이유 |
|---|---|---|
| S1 | 픽·글·댓글처럼 한도·순위·주차가 걸린 쓰기는 DB 함수(RPC)로만 한다. 앱 코드는 테이블에 직접 insert·update·delete 하지 않는다 | 2절 A안. 검사와 저장을 잠금 하나로 묶어 표가 새지 않게. RLS 가 직접 쓰기를 막는다 |
| S2 | `shared/` 는 `features/`·`app/` 을 가져오지 않는다. 기능끼리는 서로 가져와도 된다 | 공통 부품이 특정 기능에 묶이지 않게 |
| S3 | service_role 키는 Edge Function·로컬 스크립트에서만 쓴다. `app/`·`features/`·`shared/` 에는 두지 않는다 | 브라우저 번들이나 서버 컴포넌트 로그로 새지 않게(5절) |
| S4 | 색은 `shared/styles/tokens.css` 의 토큰으로만 쓴다. 메일·공유 그림·manifest 처럼 변수를 못 읽는 곳은 예외 파일에 이유와 함께 적는다 | 라이트·다크를 한 곳에서 바꾸게(DESIGN_SYSTEM.md) |

## 3-1. 구현 메모 (#2, 2026-11-18)
- 마이그레이션: `supabase/migrations/` 7개(표 → RLS → 규칙 함수 → 사진 저장소 → 외래 키 색인 → 리뷰 반영 → #4 메인·순위 변동). 원격 프로젝트에 적용한 버전 번호를 파일 이름에 그대로 쓴다. 적용한 파일은 고치지 않고 새 파일로 바꾼다.
- 권한: 화면 역할(anon·authenticated)은 표에 직접 쓰지 못한다. `entries`·`entry_photos`·`entry_views`·`comments`·`reports`·`rank_snapshots`·`sns_events`·`sns_daily`는 직접 읽지도 못하고 함수로만 받는다(가림 기간에 표 수가 새지 않게). 직접 읽을 수 있는 건 라운드 일정, 확정 결과, 내 프로필·픽·알림·푸시 구독뿐이다.
  - 새로 만드는 함수가 PUBLIC 에 열리지 않게 전역 기본 권한을 거뒀다(`IN SCHEMA` 를 붙인 회수는 전역 기본값을 못 거둔다).
  - Supabase 보안 점검은 "security definer 함수를 anon·authenticated 가 부를 수 있다" 경고를 낸다. 이 구조에서 의도한 것이다. 화면이 부를 함수만 열었고, `require_member`·`check_photos` 같은 내부 함수와 `record_view`·`ensure_month_rounds`는 닫았다. Storage·푸시 정책이 쓰는 도움 함수(`caller_is_member`, `can_upload_photo`, `photo_in_use`, `can_add_push_subscription`)는 정책이 호출자 권한으로 부르므로 회원에게 열려 있다. 돌려주는 값은 참·거짓뿐이다.
- 회원: 구글 계정이 연결된 사람. 이메일 가입은 원격 대시보드에서 꺼야 하고(설정 도구가 없어 사용자가 직접), 꺼지지 않아도 DB 함수가 회원으로 치지 않는다.
- 오류: 함수는 `P0001` + 짧은 영문 코드(`daily_limit`, `photos_locked`, `too_fast` 등, 함수 파일 머리에 목록)를 던진다. 한국어 안내는 화면이 코드에 맞춰 붙인다.
- 속도 제한: 댓글 10분에 10개, 신고 하루 30개. 익명 로그인 남용은 Turnstile(#3)과 Auth 설정으로 막는다.
- 사진: `entry-photos` 공개 버킷(데뷔 화보의 GIF·동영상 원본은 `debut-media`, 4-10). 지운 글·숨긴 글의 사진 파일과 글에 붙지 않은 채 남은 파일 정리는 #7 예약 작업. 공개 경로에 사용자 번호가 들어가는 점은 #5에서 경로 방식을 다시 본다.
- 조회수 `record_view`는 서버만 올린다(글 상세를 서버에서 그릴 때). 화면이 직접 부르면 조회수를 부풀릴 수 있어서다. Workers 에 service_role 키를 두지 않으려고 `count_view(entry, viewer, token)`을 거친다: Vault 의 `view_token`과 Worker 비밀값 `VIEW_TOKEN`이 같을 때만 센다(4-3-2).
- 내 글 목록(`my_entries`)은 확정된 순위만 보여 준다. 진행 중 순위는 게시판 목록에서 본다.
- 정책 안에서 같은 표를 직접 세면 정책이 자기 자신을 다시 불러 무한 재귀(42P17)가 난다. 개수 확인은 security definer 함수로 뺀다.

## 4. 핵심 규칙 (DB 함수)

### 4-1. `cast_pick(entry_id)` — 픽하기
1. 호출자 = `auth.uid()`. 회원 = 구글 계정이 연결된 사람(`auth.identities`를 DB에서 직접 확인). JWT의 `is_anonymous`만 보면 이메일 가입 계정이 회원으로 통과해서 쓰지 않는다. 하루 = `(now() at time zone 'Asia/Seoul')::date`.
2. 글이 열린 라운드에 있고(`now()`가 시작~끝 사이), 숨김이 아니고, 내 글이 아닌지 확인.
3. `pg_advisory_xact_lock(호출자, 하루)`로 같은 사람의 동시 픽을 한 줄로 세운다.
4. 한도 확인: 회원이 아니면(익명·이메일 가입) 오늘 전체(두 게시판 합쳐) 1픽, 회원이면 이 게시판 오늘 3픽.
5. `picks`에 넣는다. 같은 글·같은 날이 이미 있으면 유일 제약이 막는다 → "오늘 이미 픽했어요".
6. 이 게시판 남은 픽 수를 돌려준다.

### 4-2. 익명 → 구글 로그인
- 처음 픽할 때 화면이 익명 로그인(`signInAnonymously` + Turnstile 토큰)을 한다. 구경만 하는 사람은 익명 사용자를 만들지 않는다.
- 로그인 시트의 "구글로 계속하기" = `linkIdentity({ provider: 'google' })`. **사용자 번호가 그대로라 오늘 한 픽이 자동으로 이어진다.** 익명 상태에서 남은 픽은 로그인 후 한도(3)로 다시 계산된다.
- 그 구글 계정이 이미 가입돼 있으면 연결이 실패한다(`identity_already_exists`). 이때는 익명 세션 토큰을 잠시 들고 일반 구글 로그인을 한 뒤, `merge-anon` Edge Function이 두 토큰을 확인하고 익명 사용자의 픽(지난 날짜 포함)을 기존 계정으로 옮긴다(같은 글 중복·한도 초과분은 버림). 그다음 익명 사용자를 지운다.
- 구현(#3)
  - 첫 픽: `PicksProvider` → `ensureAnonSession()`(세션이 없을 때만 Turnstile 토큰 + `signInAnonymously`) → `cast_pick` → `router.refresh()`. Turnstile 스크립트는 이때 처음 받는다(구경만 하면 받지 않음). 보이지 않는 위젯이고, 드물게 사람 확인이 필요하면 화면 아래에 상자가 잠깐 뜬다.
  - 돌아오는 곳: `/auth/callback?next=<보던 경로>`(우리 사이트 경로만, `safeNext`). code 를 세션 쿠키로 바꾸고 next 로 보낸다.
  - 이미 가입된 계정: 콜백 → `/auth/merge?step=start` → 익명 access token 을 이 탭 `sessionStorage` 에 10분만 → 일반 구글 로그인(`merge=1`) → 콜백 → `step=finish` → `merge-anon` 호출 → next. 오류가 주소 `#` 뒤로 오면 서버가 못 읽어서 `step=check` 화면이 읽는다.
  - 픽 옮기기는 DB 함수 `merge_anon_picks`(service_role 만 실행). `insert` 가 아니라 `voter_id` 를 바꿔 표 수를 두 번 세지 않는다. 못 옮기는 픽(그 계정이 이미 픽한 글·그 계정 자신의 글·게시판 하루 3픽 초과)은 지우고 표 수도 내린다. `cast_pick` 과 같은 잠금을 잡는다.
  - `merge-anon` 은 두 토큰을 모두 Auth 서버로 확인한다(옮겨 받는 쪽은 구글 회원, 주는 쪽은 익명이어야). 허용 출처는 함수 비밀값 `ALLOWED_ORIGINS`. 남의 익명 토큰을 가져와도 얻는 건 그 사람의 오늘 1픽뿐이고 한도는 DB 가 지킨다.
  - 세션 갱신: `middleware.ts` 가 로그인 쿠키가 있는 요청에서만 `getClaims()` 로 만료를 보고 갱신해 쿠키를 다시 쓴다.
  - 하려던 픽 이어 하기: 픽 때문에 로그인 시트가 뜨면 그 글 번호를 이 탭 `sessionStorage` 에 15분 적어 두고(`features/auth/handoff.ts`), 회원으로 돌아온 첫 화면이 이어서 보낸다. 다른 이유로 시트를 열면 지운다.
  - 손님 첫 픽 뒤에는 `router.refresh` 를 하지 않고 화면의 viewer 만 "anon" 으로 바꾼다(새로 고치면 Providers key 가 바뀌어 더 보기로 불러온 글·스크롤이 사라진다). 첫 픽 처리 중의 다른 누름은 받지 않고, `ensureAnonSession` 도 진행 중인 것을 같이 써서 익명 사용자가 둘 생기지 않는다.
  - 구글 화면에서 취소(`access_denied`)하면 실패 화면 없이 보던 곳으로 돌아간다. 이미 가입된 계정이면 "같은 계정을 한 번 더 골라 주세요"를 먼저 보여 주고, 픽 옮기기 결과는 돌아간 화면에 토스트로 알린다.
  - 카카오톡·인스타 같은 앱 안 브라우저는 구글이 로그인을 막아서(403 disallowed_useragent), 카톡은 기본 브라우저로 열고 나머지는 "다른 브라우저로 열기"를 안내한다.
  - `merge_anon_picks` 는 받는 쪽이 구글 회원인지 DB 에서도 확인하고(`not_member`), 지난 날짜 익명 픽까지 그날 한도로 옮긴다(익명 사용자를 지울 때 cascade 로 지난 표가 사라지지 않게).
  - 돌아올 경로 `safeNext` 는 제어 문자를 거부하고 실제로 파싱한 출처로 판정한다(`/\t/evil.com` 같은 우회 차단, `next-path.test.ts`).
  - 접속 정보별 하루 한도: 회원이 아닌 픽은 `cast_pick` 이 같은 IP 의 오늘 익명 픽 수를 본다(`anon_ip_daily`, 한도 `ip_pick_limit()` = 20, 넘으면 `ip_limit` → "이 인터넷에서는 오늘 로그인 전 픽이 마감됐어요" 시트). IP 는 저장하지 않고 비밀 소금(`ip_salt`)+날짜+IP 의 sha256 만 센다. IP 는 Cloudflare 가 넣는 `cf-connecting-ip` 만 믿고, 없으면 한도를 건너뛴다.
  - 로그인 전환 기록: `record_auth(kind, detail)` 가 `auth_daily` 에 날짜·종류별 숫자만 센다(sheet 노출 이유, google 누름·앱 안 브라우저, callback ok·cancel·error·already, merge moved·dropped·failed). 누가 했는지는 남기지 않는다.
  - 응원단 로그인 시트는 sheet `cheer` 로 따로 센다(#43).
  - 알림 클릭 기록(#43): 푸시·메일 링크에 `?from=<kind>&via=<push|mail>`(`noticeLink`)을 붙이고, 첫 화면의 `NoticeClickTracker` 가 `record_notice_click(kind, via)` 로 `notice_clicks` 에 날짜·종류·경로별 숫자만 센 뒤 주소에서 뗀다. 알림함은 누를 때 `via=inbox` 로 바로 센다. (날짜, 종류, 경로) 칸마다 하루 2만에서 멈춘다(한 칸을 부풀려도 다른 칸은 계속 셈, #44). 로그인 시트 기록 `record_auth` 도 같다. 손님도 부를 수 있어 참고 숫자로만 본다.
  - 관리자 `/admin` "결선 대기 성과": `admin_revisit_stats(weeks)` 가 KST 월요일 기준 주마다 응원단 들어온 수(지금 남은 줄)·주인 답글 수·final_open 클릭 수·응원단 로그인 시트 수를 준다.
  - 지표를 회원·익명으로 나눠 본다: 주간 픽 참여자 = `select u.is_anonymous, count(distinct p.voter_id) from picks p join auth.users u on u.id = p.voter_id where p.kst_date between <주 시작> and <주 끝> group by 1`. 익명은 쿠키를 지우면 새 계정이 되므로 핵심 지표는 회원 수를 기준으로 본다.

### 4-3. `create_entry(...)` — 연습생 등록
회원(구글 연결)만. 열린 주간 라운드인지, 이 사람의 이번 라운드 등록이 2개 미만인지, SNS 주소가 프로필 주소 형식(instagram.com/아이디, threads.com/@아이디(threads.net 도), youtube.com/@아이디·channel/번호)인지 확인. 사진은 내 폴더에 실제로 올라온 파일만, 같은 파일을 두 번 쓰지 못한다. 이름·소개에 보이지 않는 글자(방향 바꾸기 등)는 거절.

### 4-3-1. `update_entry(...)`·`delete_entry(id)` — 내 글 고치기·지우기
1. 글을 `select … for update`로 잠근다. `cast_pick`이 `pick_count`를 올릴 때도 같은 줄을 잠그므로, "픽 0개 확인 → 사진 바꾸기"와 첫 픽이 동시에 와도 한쪽이 기다린다.
2. 주인인지, 지우거나 숨긴 글이 아닌지, 라운드가 아직 열려 있는지 확인한다.
3. 이름·소개·SNS는 그대로 고친다(SNS 형식 검사는 등록과 같음).
4. 사진 목록이 바뀌었으면 `pick_count = 0`이고 결선 글이 아닐 때만 `entry_photos`를 바꾼다. 아니면 `photos_locked` 오류. 빠진 파일 중 다른 글이 쓰지 않는 것만 `removed`로 돌려주고, 화면이 Storage에서 지운다(글에 붙은 파일은 Storage 정책이 지우기를 막는다).
5. `delete_entry`는 `deleted_at`만 찍는다(등록 횟수 계산에 그대로 남아 다시 올려도 2번 제한이 유지됨). 결선 진출 글이면 `prepare_final`·`get_featured`가 3위 승계 규칙대로 다음 글을 쓴다.

### 4-3-3. 내 정보·탈퇴 (#5, 결정기록 2026-11-18)
- `/me`(회원만): 닉네임 바꾸기, 내 글 목록(`my_entries`, 투표 중인 글만 고치기·지우기), 로그아웃, 회원 탈퇴. 윗줄 오른쪽 끝에 회원이면 "내 정보"가 휴대폰·데스크톱 모두 보인다.
- `set_nickname(nickname)`: 2~12자·보이지 않는 글자 거절, 마지막으로 바꾼 지 7일이 안 됐으면 `nickname_cooldown`(detail 에 다시 바꿀 수 있는 시각). 같은 이름이면 쿨타임 없이 그대로 둔다. `profiles.nickname` 직접 고치기 권한은 걷었다.
- 탈퇴: 화면 확인 시트 → Edge Function `delete-account`가 토큰을 Auth 서버로 확인(익명 거절) → 내 Storage 폴더 목록을 읽고 → 계정 삭제 → 사진 파일 삭제. 글·사진 줄·댓글·신고·알림은 on delete cascade, 남에게 준 픽은 `voter_id`만 비워 남긴다(받은 쪽 표 수 그대로). 결선 진출 글이 사라지면 4-3-1 의 3위 승계 규칙을 그대로 쓴다. 허용 출처는 `merge-anon`과 같은 `ALLOWED_ORIGINS`.
  - 예외: **오늘 준 픽은 지운다**(`delete_today_picks`, service_role 전용). 탈퇴 → 같은 구글 계정 재가입은 새 사용자 번호라 하루 한도가 새로 생겨, 오늘 픽을 남기면 같은 글에 표를 끝없이 줄 수 있다.
  - 최근 10분 안에 로그인한 토큰만 받는다(`amr` 시각, 아니면 403 `reauth_required`). 화면은 미리 같은 규칙(`signedInWithin`)으로 보고 구글 계정 고르기(`prompt=select_account`)를 거쳐 `/me?leave=1`로 돌아온다.
  - Storage 목록을 못 읽으면 계정을 지우지 않는다. 지운 뒤 한 번 더 읽어 그사이 올라온 파일도 지운다. 업로드 이름은 `내 폴더/영숫자.webp|jpg` 한 단계만 받는다(`can_upload_photo`).
- 봇·악성 계정 정리: 계정을 지우기 **전에** `purge_bot_picks(uid)`(service_role 전용)로 결과가 확정되지 않은 라운드의 픽을 지운다. 그 뒤 계정 삭제는 탈퇴와 같은 길. 관리자 화면 버튼은 #6.
- 등록하면 상세로 `?new=1`을 붙여 보내 공유 띠(`NewEntryBanner`)를 띄우고, 띠는 주소에서 표시를 지운다.
- 밖으로 나가는 주소는 글 상세(공유하기)와 메인뿐이다. `/register`는 공유 버튼이 만들지 않고 검색에서도 뺀다(`noindex`). 홍보·SNS 에도 등록 주소를 쓰지 않는다.
- 등록 화면의 남은 횟수는 `my_entries_left()`로 받는다(지운 글까지 셈, `create_entry`와 같음). 올릴 수 없는 때는 폼 대신 안내를 먼저 보여 준다.
- 등록 화면 `/register`: 한 화면 폼 + 미리보기(휴대폰은 위아래, 데스크톱은 왼쪽 폼·오른쪽 미리보기). 사진은 고르는 즉시 1600·480 WebP 로 다시 그리고(1-7, WebP 를 못 만드는 사파리는 JPEG), 글자는 localStorage·사진은 IndexedDB 에 임시 저장해 로그인 시트를 다녀와도 이어 쓴다. 다 쓰고 "등록하기"를 눌렀는데 로그인 전이면 로그인 시트(`submit`)를 띄우고, 로그인 뒤 `/register?submit=1`로 돌아와 임시 저장을 불러온 다음 한 번 바로 등록한다(주소 표시는 지워 새로고침해도 두 번 올라가지 않는다). 빠진 칸이 있으면 오류만 보여 준다. 등록·로그아웃·탈퇴 때 지운다. 고치기는 `/dog/<글>/edit`에서 같은 폼을 쓴다.

### 4-3-2. 이름 검색·조회수
- `board_entries(board, sort, q)`의 `q`가 두 글자 이상이면 그 라운드·게시판 안에서 `pet_name ilike '%q%'`로 거른다. 한 라운드 글 수가 많아야 수천 개라 `(round_id, board)` 인덱스로 충분하고, 따로 검색 엔진은 두지 않는다. 가림 기간 규칙(표 수 숨김·섞어 보기)은 검색 결과에도 똑같이 적용한다.
- 글 상세를 서버에서 그릴 때 응답을 보낸 뒤(`after`) `count_view`를 부르고, 그 안에서 `record_view(entry_id, viewer_key)`를 부른다. `entry_views`에 넣기가 성공한 경우에만 `view_count`를 1 올린다. 봇·미리보기 요청(User-Agent)과 내 글·숨김 글은 세지 않는다(`features/entries/views.ts`).
- 보는 사람 키: 로그인(익명 포함)이면 사용자 번호, 손님이면 `cf-connecting-ip`. 둘 다 토큰과 섞은 SHA-256 만 보낸다. 손님을 쿠키가 아니라 IP 로 세는 이유는 서버 렌더 첫 방문에 쿠키가 없고, 쿠키는 지우고 다시 오면 끝없이 늘릴 수 있어서다. 같은 와이파이 여러 명이 하나로 세지는 것은 감수한다.
- 게시판 검색칸은 서버가 그리는 GET 폼(`/dog?q=콩이`)이라 스크립트 없이도 동작한다. 정렬을 바꿔도 검색어를 유지하고, "더 보기"도 같은 검색어로 이어 부른다. 순위 알약은 게시판 전체 순위 그대로다. 검색 결과 주소는 `noindex`.
- 가림 기간에는 `view_count`도 `null`로 준다(조회수로 순위를 짐작하지 못하게).

### 4-3-4. 댓글·신고·관리자·알림함 (#6)
- 댓글: 글 상세 아래 `entry_comments`(최신순 30개 + 전체 수 `total`). 쓰기는 회원만 `add_comment`(100자, 10분에 10개, 숨은 글자·금지어 거절). 10개 한도는 회원별 잠금(`pg_advisory_xact_lock`)을 잡고 세서 동시 요청으로 뚫리지 않는다.
- 손님 댓글 이어 하기: "남기기"를 누르면 쓴 글을 탭(sessionStorage)에 적어 두고 로그인 시트를 띄운다. 회원으로 돌아오면 그 글에 한 번 바로 올린다. 시트를 닫거나 다른 이유로 시트를 열면 적어 둔 글을 지운다(나중에 다른 로그인 뒤 저절로 올라가지 않게). 카톡·인스타 앱 안 브라우저는 기본 브라우저로 옮기며 저장 공간이 끊기므로, 쓴 글을 주소의 `cm` 값에 붙여 넘기고 새 브라우저의 글 상세가 입력칸을 다시 채운다(주소에서는 바로 뗀다).
- 금지어: `has_banned_word(text)` 한 곳. 세 갈래로 본다. ① 흔한 낱말 속 것(시발점·졸라맨·아저씨·아가씨)을 띄어쓰기가 남은 채 먼저 지운다. ② 다른 낱말과 섞이기 어려운 긴 욕설은 한글·영문 말고 모두 빼고 찾는다(띄어쓰기·기호·숫자 우회). ③ 짧아서 낱말 사이에 우연히 생기는 것(도시 발전의 "시발", 강아지 게시판의 "개 새끼들")은 붙어 있을 때만 찾는다. 영문은 NFKC 로 전각을 접는다. 걸리면 `banned_word` 로 거절하고, 화면은 입력칸 아래에 안내하고 글을 남긴다. 빠진 것은 신고로 처리한다.
- 신고: 글·댓글 모두 `report(target, id)`. 사유는 고르게 하지 않는다(관리자가 대상을 직접 본다). 같은 사람·같은 대상은 한 번.
- 관리자 `/admin`: `profiles.is_admin` 회원만(아니면 404). `admin_reports`(처리 안 된 신고를 대상별로 묶음, 대상이 통째로 지워진 신고는 뺌) · `admin_set_hidden`(숨기기·되살리기, 신고 닫음) · `admin_dismiss`(문제없음, 주인이 지운 대상은 "닫기") · `admin_recent_hidden`(지난 14일 숨긴 것, 되살리기용) · `admin_remove_reply`(댓글 신고 줄에 보이는 글 주인 답글만 지움, 신고는 열어 둠, #40). 모두 `require_admin()`으로 다시 확인한다. 관리자 지정은 SQL 로만.
- 봇 계정 정리: 관리자 화면 "계정 정리" → Edge Function `admin-purge-user`(관리자 확인 → 최근 10분 안 구글 재로그인 확인(아니면 403 `reauth_required`, 화면이 구글로 다시 확인받음. 관리자는 `max_age=0`으로 다시 로그인을 요구. 규칙은 화면·함수가 함께 쓰는 `supabase/functions/_shared/reauth.ts` 한 곳) → 자기 자신·관리자 거절 → 계정 막기(`banned_until`) → 처리 기록 → `purge_bot_picks` → 사진 목록 → 계정 삭제 → 사진 삭제 → 처리 기록). 막힌 계정은 이미 받은 토큰으로도 픽하지 못한다(`picks` 넣기 전 트리거 `picks_block_banned`). `purge_bot_picks` 는 `cast_pick` 과 같은 "사람·날짜" 잠금을 오늘·어제 둘 다 잡아, 막기 전에 시작된 픽이 끝난 뒤에 지운다.
- 관리자 처리 기록 `admin_actions`: 숨기기·되살리기·문제없음·답글 지우기(`admin_set_hidden`·`admin_dismiss`·`admin_remove_reply` 안에서)과 계정 정리(Edge Function)를 한 줄씩 남긴다. 화면 역할은 읽지도 쓰지도 못하고, service_role 도 덧붙이기만 한다. 관리자 SQL 로만 본다. 라운드 결과 다시 계산 버튼은 #7 결과 확정과 함께.
- 알림함: 내 정보(`/me`)에 최근 20개. 화면을 열면 20개 밖의 것까지 안 읽은 것을 모두 읽음으로 바꾼다(RLS 로 내 알림의 `read_at`만). 못 읽으면 빈 상태 대신 "불러오지 못했어요". 회원이면 레이아웃이 안 읽은 수를 같이 읽어 "내 정보" 옆에 점을 찍는다. 문구는 `features/notifications/text.ts`(comment·center·finalist·debut, 모르는 종류는 일반 문구).

### 4-4. 자정 작업 `midnight_jobs()` — 매일 00:00 KST(UTC 15:00) pg_cron `pd-midnight` (#7)
마이그레이션 `20261118150000_schedule.sql`. 단계마다 따로 잡아 하나가 실패해도 다음 단계는 돈다. 예약 작업이 하루 밀려도 다음 실행이 밀린 라운드까지 확정한다.
1. `ensure_month_rounds()`로 이번 달·다음 달 라운드 4개씩을 만든다(멱등). 주간 1·8·15일 시작(1·2주차 7일, 3주차는 20일까지 6일, #41), 21일은 열린 라운드 없음, 결선은 22일 0시 ~ 다음 달 1일 0시(28~31일 달 모두 시험).
2. `finalize_due_rounds()` → 라운드마다 `finalize_round(id)`:
   - 라운드 줄을 잠그고(관리자 재계산과 겹치지 않게), 게시판마다 숨김·삭제 아닌 글을 `picks`로 다시 세어 위 10개를 `round_results`에 쓴다. 0표 글은 빠진다.
   - 동점은 **그 표 수에 먼저 도달한 글**(마지막 표의 `created_at`이 이른 쪽), 그것도 같으면 먼저 올린 글이 위.
   - 주간 1위 `center`(결선에도 오름), 2위 `finalist`. 결선 1위 `debut`.
   - 이 라운드에서 그 (글, 역할) 알림을 아직 안 받은 주인에게만 `notifications`를 넣는다. 다시 계산해도(숨김을 켰다 껐다 해도) 한 번.
   - 노출이 끝난 라운드(`result_exposure_over`: 주간은 뒤 라운드가 끝남, 결선은 끝난 뒤 한 달)는 결과만 바꾸고 새 알림은 넣지 않는다.
   - 다시 계산으로 1·2위에서 밀린 글 주인에게는 알림함에만 `result_changed` 정정 알림(메일·푸시 없음).
3. `prepare_final(month)`: 그달 주간 라운드가 모두 확정됐고 결선이 아직 안 끝났으면, 주간 라운드·게시판마다 보여 줄 수 있는 위 2개를 결선 라운드로 복사한다(사진 줄 포함, `source_entry_id`로 원본 표시). 매일 다시 불러, 복사본이 지워졌거나 숨겨지면 그 라운드 다음 순위가 이어받는다. 한 번 올라간 원본은 다시 복사하지 않는다.
3-1. `notify_final_open()`(#39): 결선이 열려 있으면, 결선 복사본(살아 있는 것)의 원본 글 응원단에게 `final_open` 알림(결선 복사본 주소, emailed_at 을 채워 푸시만)을 넣는다. 같은 사람·같은 결선 글은 한 번. 3위가 이어받으면 다음 날 그 아이 응원단에게도 간다.
3-2. `report_centers()`(#39): 센터 노출이 끝난(뒤 라운드가 끝난) 주간 라운드의 센터마다, 노출 기간(뒤 라운드의 KST 날짜) `sns_events` 의 instagram·threads·youtube 방문자 수를 세어 `center_reports`에 한 번 남기고 주인에게 `center_report` 알림(푸시만)을 넣는다. 끝난 지 14일이 넘은 라운드는 건너뛴다(배포 전 옛 라운드에 몰아 보내지 않게).
4. `snapshot_ranks()`로 순위 변화 기록, 오래된 기록 정리(조회 30일, SNS 90일, 순위 60일, 응원단 90일).
5. `kick_dispatch()`: 최근 3일 결과·결선 시작·센터 성과 알림 중 메일·푸시를 못 보낸 것이 있으면 pg_net으로 Edge Function `dispatch-notifications`를 부른다. 주소는 Vault `project_url`, 확인 토큰은 Vault `dispatch_token`(마이그레이션이 DB 안에서 만들어 밖으로 나가지 않음). 결선 시작(`final_open`)·센터 성과(`center_report`) 푸시는 `push_ready_at(kind, created_at)`(만든 날 KST 9시)이 지나야 보낼 거리에 들어가고, pg_cron `pd-morning-push`(UTC 0시 0·10·20분 = KST 9시대, 실패한 푸시를 다시 시도)가 `kick_dispatch()`를 더 부른다(#42·#44). 알림함에는 0시에 바로 쌓인다.

**알림 발송 `dispatch-notifications`** (verify_jwt 끔, 헤더 `x-dispatch-token`을 `dispatch_token_ok()`로 확인)
- `dispatch_queue()`로 보낼 거리(메일 주소 포함, service_role만)를 읽어 메일(Gmail SMTP 465, 연결 하나로 차례로 보내고 로그인이 거절되면 남은 메일은 다음 실행으로)과 웹 푸시(VAPID, 410·404 구독은 지움)를 보내고 `mark_dispatched()`로 표시한다.
- 비밀값이 없는 채널은 건너뛰고 표시하지 않는다(설정 뒤 다음 실행 때 보냄). 일시 오류도 표시하지 않아 다음 실행 때 다시 보낸다. 알림함 줄은 발송과 상관없이 남는다.
- 문구는 `supabase/functions/_shared/notice.ts` 한 곳(화면 알림함과 함께 씀).
- 데뷔(kind debut) 메일만 본문이 따로다(#27, `_shared/debutMail.ts`): 제목 "‘이름’ 데뷔 확정! 화보 사진을 올려 주세요", 분홍 버튼 "화보 사진 올리기"(그 글의 `/gallery`), 노출 가이드 그림(`public/mail/debut-guide.jpg`, 실제 메인 댕댕이 보기·데뷔 화보 캡처에 자리 번호 1~5), 자리 설명(1·2 원래 사진, 3·4·5 화보 사진), 사진 고르는 요령. 화면 배치가 바뀌면 가이드 그림을 다시 찍는다.

**푸시 구독**: 내 정보 알림함 위 "이 기기에서 알림 받기"(`PushToggle`). 알림 허락(누른 순간) → `/sw.js` 등록 → 구독 → `push_subscriptions`(RLS 내 것만, 10개까지). 켜짐 여부는 이 기기 구독이 내 계정 줄인지로 판단하고, 로그아웃·탈퇴 때 이 기기 구독을 푼다(같은 기기의 다른 계정에게 알림이 섞이지 않게). 아이폰·아이패드는 홈 화면에 추가한 앱에서만 되므로, 사파리에서는 공유 버튼의 "홈 화면에 추가" 안내를 보여 준다(#8 manifest). 공개 키 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`가 없으면 칸이 숨는다.

**관리자 다시 계산**: 관리자 화면 맨 아래 "라운드 결과"(`admin_rounds()`, 최근 끝난 8개, 게시판별 1·2위와 노출 끝남 표시). 끝나면 토스트로 1·2위가 바뀌었는지·알림 받은 수를 알린다. `admin_recalculate(id)`가 확정을 다시 돌리고 주간이면 결선 준비도 다시 돌린 뒤 발송을 깨운다. `admin_actions`에 `recalc`로 남는다(대상 `round`, 번호는 detail).

### 4-5. 가림 기간(마감 24시간 전 ~ 결과 확정)
`board_entries(board, sort)` 함수가 화면용 목록을 준다. 줄마다 오늘 0시 순위 `prev_rank`도 같이 준다(#4, 차트 ▲▼). 가림 기간은 마감 24시간 전부터 `finalized_at`이 찍힐 때까지다(예약 작업이 늦어도 확정 전 표 수가 먼저 보이지 않게). 가림 기간에는 표 수·순위·`prev_rank`를 `null`로, 인기순 요청을 **섞어 보기**(오늘 날짜 + 사용자 번호로 고정된 무작위 순서)로 바꿔 준다. 손님은 사용자 번호가 없어 화면이 방문자 키 쿠키 `pd_vid`를 `p_seed`로 넘긴다(#11). 첫 방문(쿠키가 아직 없음)만 손님 공통 순서다. 이어 불러오기도 서버가 쓴 seed 를 그대로 넘겨 순서가 이어진다. 테이블을 직접 읽는 길은 RLS로 막아서 표 수가 새지 않게 한다.

### 4-6. 1위 노출 `get_featured()`
- 이달의 데뷔: 지난달 결선 1위 두 마리(강아지·고양이). 다음 달 1일~말일 노출.
- 이번 주 센터: 가장 최근 확정된 주간 라운드 1위 두 마리. 다음 라운드 기간 노출.
- 데뷔조 후보: 이번 달 주간 라운드마다 보여 줄 수 있는 글 중 위 2개(1·2위가 숨겨지면 3위가 이어받는다).
- 숨김·삭제된 글은 건너뛰고 다음 순위를 보여 준다. 카드마다 `pos`(그 라운드에서 숨김을 건너뛴 순서)를 주고, 화면은 `pos = 1` 을 그 라운드 센터로 쓴다.
- 명예의 전당 `hall_of_fame(p_months)`(#8)은 기록이라 이 규칙을 따르지 않는다. 1위가 숨겨지거나 지워지면 2위를 올리지 않고 그 자리를 `hidden: true`(이름·사진·표 수·글 번호 없음)로 주고, 화면은 "공개되지 않은 1위" 빈 카드를 둔다(2026-11-19 사용자 결정).
- 데뷔 항목에만 사진 전부(`photos`, 순서대로)를 싣는다(#16). 메인 세로 배너·표지가 여러 장이면 자동으로 넘긴다. 데뷔는 게시판마다 하나라 많아야 두 글이다.
- #25 메인 표지 "내 쪽 먼저": 게시판·글 상세에 들어오면 `SiteNav` 안의 `RememberBoard` 가 그 게시판을 쿠키(`pd-board`)에 둔다(#26 에서 localStorage → 쿠키, 서버가 읽도록). 전체 보기의 `Cover` 는 그쪽 데뷔 장부터 보여 준다.
- #26 메인 보기 토글(전체·댕댕이·냥이): `ViewToggle` 이 쿠키 `pd-view` 에 두고 `router.refresh()`. `MainPage` 가 `resolveView(pd-view, pd-board)`(고른 값 → 마지막 게시판 → 전체)로 보기를 정해 `filterFeatured` 로 데뷔·센터·후보를 그 게시판만 남기고, 차트는 그 게시판 6줄(`Chart only`), 모집 포스터도 그 게시판 사진. 1280 이상 양옆 세로 배너는 둘 다 그 게시판 데뷔 아이: 왼쪽 원래 사진 + SNS, 오른쪽 `variant="gallery"` 는 `get_featured_at` 데뷔 항목의 `gallery`(debut_photos)를 넘기고 없으면 얼굴 쪽으로 당긴 구도, 아래는 "화보 보러 가기"(같은 아이 SNS 를 두 번 세지 않게). 표지 아래 대각선 배너(`DebutDuo same`)도 두 칸 모두 그 아이(원래 사진 · 화보 사진 마지막 장). 표지 이름 밑(표 수 판 옆)에는 모든 폭에서 SNS 아이콘을 둔다: 장을 `div`로 두고 글 상세 링크(`.slideLink`)는 장을 덮게, 글줄은 그 위 형제로 `pointer-events: none`, 아이콘 칸만 다시 받는다(링크 안 링크를 피함). 노출은 장마다 `Impression`(place cover)이라 넘김 틀 밖 장은 세지 않는다. 메인은 원래 로그인 쿠키를 읽어 사람마다 그리므로 쿠키 하나 더 읽어도 캐시 손해가 없다. 토글은 #25 때 단점만 보고 뺐다가, 사용자 의견(한쪽 보기면 배너까지 통일)으로 넣었다.
- 화면은 인자 없는 `get_featured()` 만 부른다. 기준 시각을 받는 본체 `get_featured_at(p_at)` 은 시험용이라 화면 역할에 닫혀 있다(시각을 바꿔 부르는 길을 열어 두지 않으려고). 본체는 확정된 결과만 돌려줘야 하고, 최근 두 달 결과만 훑는다.
- `role` 칸 대신 순위로 고른다(#4 구현). `role` 은 줄마다 하나라 "주간 1위 = 센터이면서 후보"를 담지 못한다. `role` 은 알림 문구용으로 둔다.
- 메인(데스크톱)의 센터 화보 4칸은 이번 주 센터 2장 + 이번 달 지난 라운드 1위 2장이다(후보 목록에서 1위만 골라 쓴다).

- 게시판·글 상세 맨 위에는 **센터 띠**(이번 주 강아지·고양이 1위, 이름 → 글 상세, 옆 글자 → SNS)를 둔다. 메인은 센터 화보가 같은 일을 해서 띠를 두지 않는다. 한 요청에서 띠와 메인이 같이 불러도 `get_featured` 는 한 번만 부른다(React `cache`).

### 4-8. SNS 이동률 기록 `record_sns(entry_ids, kind, place, viewer_key)` (#11)
- #16 메인 세로 배너(1280px 이상)와 1024~1279 펼침면의 SNS 아이콘은 표지와 같은 자리 `cover` 로 센다. 화면 폭으로 나뉘어 한 사람이 둘을 동시에 보지 않는다. 배너만 따로 보려면 `place` 허용값에 `rail` 을 더한다(나중 일).
- 기획서 성공지표 "배너 SNS 이동률" = SNS 클릭 ÷ 노출. 노출은 그 영역이 화면에 절반 이상(또는 화면 절반 이상을 채울 때) 처음 보일 때(`IntersectionObserver`, `intersectionRatio`로 확인), 클릭은 SNS 링크를 누를 때 남긴다. 노출은 SNS 칸이 실제로 보이는 글만 센다: 표지는 휴대폰에서 지금 넘겨 둔 장(데스크톱은 SNS 버튼이 없어 세지 않음), 센터 화보·띠는 SNS 있는 이번 주 센터만(지난 라운드 센터 카드엔 SNS 칸을 두지 않는다).
- 손님도 부른다(서버 키 없이). 같은 사람(방문자 키)·날·글·자리·종류는 한 번만 센다. 숨김·삭제 글과 모르는 종류·자리는 버린다. 한 번에 8개까지.
- 화면은 supabase-js 없이 PostgREST 에 `fetch(keepalive)` 한 번만 보낸다(새 탭으로 나가도 끝까지 간다). 실패해도 화면은 아무것도 하지 않는다.
- 한계: 키를 바꿔 가며 부르면 숫자를 부풀릴 수 있다. 지표용 기록이라 표·순위에는 영향이 없어 감수한다.
- 저장량 상한: 같은 방법으로 표를 끝없이 키우는 것은 감수하지 않는다. `sns_daily`(날짜별 줄 수)가 하루 20만 줄을 넘으면 그날은 더 쌓지 않는다(줄당 약 225B, 하루 최대 약 45MB). 90일 지난 줄은 #7 자정 작업에서 지운다(그 전까지 쌓이는 양은 상한으로 묶인다).
- 종류·자리가 비거나 모르는 값이면 오류 없이 0 을 돌려준다.
- 이동률 보기(관리자 SQL):
  ```sql
  select kst_date, place,
         count(*) filter (where kind <> 'view') as clicks,
         count(*) filter (where kind = 'view')  as views,
         round(100.0 * count(*) filter (where kind <> 'view') / nullif(count(*) filter (where kind = 'view'), 0), 1) as rate_pct
    from public.sns_events
   where kst_date >= public.kst_today() - 7 and place in ('cover', 'center', 'banner')
   group by 1, 2 order by 1 desc, 2;
  ```

### 4-9. 공유 기록 (#15)
- 같은 `record_sns` 로 남긴다. 종류: `share_sheet`(휴대폰 공유 창에서 보내기를 마침) · `share_copy`(문구 복사) · `share_manual`(복사가 막혀 직접 고르는 칸을 띄움) · `share_visit`(공유 주소로 들어옴). 자리: `detail`(글 상세) · `register`(등록 직후 띠).
- 공유 문구 주소에는 `?ref=share` 를 붙인다(`features/share/link.ts`). 글 상세의 `ShareVisit` 가 그 표시를 보면 방문을 한 번 남기고 주소창에서 뺀다(다시 공유·새로고침이 방문으로 섞이지 않게). 미리보기를 가져가는 메신저 봇은 스크립트를 돌리지 않아 세지 않는다. `og:url` 은 `ref` 없는 주소다.
- 같은 사람·날·글·자리·종류는 한 번, 하루 상한·90일 정리는 4-8 과 같다. 첫 픽과 잇는 것은 하지 않았다(방문자 키로 이어 볼 수는 있다).
- 보기(관리자 SQL):
  ```sql
  select kst_date,
         count(*) filter (where kind in ('share_sheet', 'share_copy', 'share_manual')) as shares,
         count(*) filter (where kind = 'share_visit') as share_visits,
         count(*) filter (where kind = 'share_sheet') as by_sheet,
         count(*) filter (where kind = 'share_copy') as by_copy,
         count(*) filter (where place = 'register' and kind <> 'share_visit') as from_register
    from public.sns_events
   where kst_date >= public.kst_today() - 7 and kind like 'share%'
   group by 1 order by 1 desc;
  ```

#### 데뷔 화보 맺음 기록 (#31)
- 표지 SNS·공유(2026-11-20 사용자 결정): 자리 `debut_cover`. 표지 SNS 줄이 화면에 절반 넘게 보이면 `view`(공유하기는 늘 있으므로 SNS 가 없는 글도 남긴다. SNS 유무는 분석에서 나눈다), SNS 아이콘·공유하기를 누르면 그 종류를 남긴다. 아래 SNS 칸(`debut`)과 나눠 어느 자리가 팔로우·공유를 데려오는지 본다.
- 화보를 끝까지 본 사람이 투표로 얼마나 가는지 센다. 자리 `debut_back`(화보 맺음), 종류 `view`(맺음이 화면에 절반 넘게 처음 보임) · `pick_cta`(맺음의 "{게시판} 연습생 픽하러 가기" 클릭). 화보 상세 노출(`debut`)과 자리를 나눠야 같은 사람·날·글·자리·종류 한 번 규칙에 묻히지 않는다(`20261120070612_debut_back_track.sql`).
- 맺음 지면은 자식 선택자로 꾸며 감쌀 수 없으므로 `useImpression(ref, ids, place)` 훅을 그 지면 ref 에 단다(`Impression` 도 이 훅을 쓴다).
- 보기(관리자 SQL):
  ```sql
  select kst_date,
         count(*) filter (where kind = 'view') as back_views,
         count(*) filter (where kind = 'pick_cta') as pick_clicks
    from public.sns_events
   where kst_date >= public.kst_today() - 7 and place = 'debut_back'
   group by 1 order by 1 desc;
  ```
- 해석 주의: 사진이 한 장뿐인 화보는 지면이 표지 → 맺음이라 거의 스크롤하지 않아도 맺음 `view` 가 남는다. 전환율은 화보 칸 수로 나눠 본다.

### 4-9-1. 결선 대기: 응원단·주인 답글·센터 성과 (#39)
- `cheer_state(entry_id)`: 주간 1·2위 글이나 그 결선 복사본이면 `{open, count, mine, is_owner, final_starts_at, final_entry_id, final_ended, is_final}`, 아니면 null. `final_entry_id`는 결선이 열린 뒤에만 준다. open 은 원본이 주간 1·2위(확정 결과의 center·finalist)이고 그달 결선이 아직 안 열렸을 때. 응원 수는 원본 글 기준이라 결선 글에서도 같은 수가 보인다. 누구나 부른다.
- `set_cheer(entry_id, on)`: 회원만(`require_member`, 손님은 화면이 로그인 시트). open 이 아니면 `cheer_closed`, 내 글이면 `own_entry`. 넣기·빼기는 멱등이고 바뀐 응원 수를 돌려준다.
- `reply_comment(comment_id, body)`: 그 댓글이 달린 글의 주인만, 남의 댓글에만(`not_owner`·`own_comment`). 글자 검사는 `add_comment`와 같다. 답글은 한 번만(두 번째는 `already_replied`: 알림 뒤에 몰래 바꾸지 못하게, #39 보안 리뷰). 댓글 쓴 사람에게 `comment_reply` 알림(알림함만). 답글은 따로 신고하지 않고 댓글 신고로 들어오며, 관리자가 지우면 `reply_body`만 비우고 `replied_at`은 남겨 다시 달지 못한다(#40).
- `my_finalist_stats()`: 내 주간 글 중 최근 60일에 1·2위가 된 것마다 역할·응원 수·센터 성과(아직 안 셌으면 null)·결선이 열렸는지(`final_open`). 내 정보 "결선 진출 현황"이 쓴다. `final_ended`(결선이 끝났는지)·`center_done`(센터 노출 기간이 끝났는지)으로 문구를 고른다.
- 센터 성과의 "사람"은 방문자 쿠키 `pd_vid`(브라우저마다 임의 번호) 기준이다. 구경만 하는 손님은 로그인 계정이 없어서, 계정 id 대신 이미 조회수·SNS 노출에 쓰던 같은 열쇠로 하루 한 번만 센다(`sns_events` 유일 키).
- 화면: `features/cheer/CheerBox.tsx`(글 상세, 댓글 위. 손님·익명은 `savePendingCheer` 뒤 로그인 시트 `cheer`, 회원으로 돌아오면 한 번 바로 들어감), `features/comments/Comments.tsx`(주인에게 "답글 달기", 답글은 "주인 답글" 칸으로 모두에게 보임. 화면은 처음 답글만 쓰게 한다), `features/me/FinalistStats.tsx`(숫자만). 문구·오류 코드는 `features/cheer/rules.ts`.
- 응원은 `picks`·`round_results`와 따로라 표 수·순위에 영향이 없다(pgTAP `cheers.test.sql`이 확인).
- 3주차 결과는 결선 시작과 같은 자정에 확정돼 응원단을 모을 틈이 없다. 그래서 3주차 center·finalist 알림은 "응원단을 모아 보세요" 대신 "오늘부터 데뷔 평가가 열려요"를 쓴다(`notice.ts`, payload.round_seq). 3주차의 응원 창을 따로 둘지는 열린 질문.
- 결선 시작 알림은 응원단 한 사람마다 한 줄이라 하루 100줄을 넘을 수 있다. `dispatch_queue(p_limit, p_after)`로 이어 받고, `dispatch-notifications`가 100줄씩 받아 보내고 표시하기를 큐가 빌 때까지(약 100초 한도) 되풀이한다. 같은 사람·같은 결선 글 알림은 유일 색인(`notifications_final_open_idx`)이 한 번으로 막는다. 응원단에 들어간 직후 이 기기 알림이 꺼져 있으면(`detectPush` = off) 켜기 시트를 한 번 띄우고, 켜기는 내 정보의 알림 칸과 같은 `enablePush`를 쓴다(#42).

### 4-10. 데뷔 화보 (#17)
- **데뷔 판정 `is_debut(entry_id)`**: 메인 표지(`get_featured_at` debut)와 같은 규칙이다. 확정된 결선 라운드에서 게시판마다 보여 줄 수 있는(숨김·삭제 아님) 글 중 가장 높은 순위. 1위가 숨겨지면 2위가 이어받는다. 실행 권한은 아무 롤에도 주지 않고 다른 함수 안에서만 쓴다.
- **사진 두 갈래**: 투표에 쓴 원래 사진(`entry_photos`, 1~3장)은 그대로 잠근다(표를 모은 사진 바꿔치기 방지). 화보 사진은 따로 `debut_photos`(0~20칸, #31에서 10 → 20, 정책 없는 RLS = 직접 읽기·쓰기 불가)에 둔다.
- **`set_debut_photos(entry_id, photos)`**: 로그인 회원 → 글 줄 잠금(for update) → 주인·숨김·삭제·데뷔 확인 → `check_photo_set(uid, photos, 0, 10)`(내 폴더·webp/jpg·실제 파일·중복 없음) → 어느 글의 투표 사진과도 같은 파일 금지 → 목록 통째 교체 → 다른 글·화보가 쓰지 않는 빠진 옛 파일만 `removed` 로 돌려준다. 화면은 그 파일만 Storage 에서 지운다(등록 폼 `update_entry` 와 같은 흐름).
- **파일 보호**: Storage 지우기 정책의 `photo_in_use` 가 화보 파일도 쓰는 중으로 본다(직접 지우기·다른 글 고치기·탭 두 개 경쟁으로 화보가 깨지지 않게).
- **데뷔가 풀리면**(숨긴 1위가 되돌아옴 등): `get_entry` 는 화보를 내주지 않고, 주인은 빈 목록으로 비우는 것만 할 수 있다.
- **GIF·동영상(#31, 2026-11-19 사용자 결정)**: 화보 칸에 `kind`(photo|gif|video). 동영상 15초·20MB·2개, GIF 원본 5MB, 모두 합쳐 20칸(2026-11-20 사용자 요청으로 10 → 20).
  - 원본은 새 공개 버킷 `debut-media`(20MB, gif/mp4/webm/mov). 데뷔한 글(숨김·삭제 아님)의 주인만 자기 폴더에 44개까지 올린다(`can_upload_media`, 20칸을 통째로 바꾸는 도중 옛 20 + 새 20 + 여유). 사진 버킷 `entry-photos` 는 폴더당 120개(화보 옛 40 + 새 40 + 투표 글 사진). 지우기는 `photo_in_use` 가 아닌 것만(지우고 같은 이름으로 다른 내용을 올려 검사를 피하는 길을 막음). 덮어쓰기(update) 정책은 없다.
  - 첫 장면 그림(thumb_path)은 `entry-photos` 에 WebP·JPEG 로. 화면은 확장자로 버킷을 고른다(`isMediaPath`).
  - `set_debut_photos` 는 `check_gallery_set` 으로 종류마다 경로·확장자·버킷·실제 크기(`metadata.size`, 모르면 거절)·동영상 개수를 다시 본다. 15초는 DB 가 모르므로 브라우저에서만 본다(크기 한도가 실제 비용을 막는 선).
  - 동영상(MP4·MOV)은 올리기 전에 `udta`·`meta`·`uuid` 상자를 0으로 채우고 `free` 로 바꿔 촬영 위치를 지운다(`videoMeta.ts`, 크기를 지켜 chunk offset 이 어긋나지 않음). 구조를 못 읽으면 받지 않는다. WebM 은 카메라가 쓰지 않아 손대지 않는다.
  - 첫 장면을 못 그리는 동영상(크롬의 아이폰 HEVC 등)은 받지 않는다. 길이는 `loadedmetadata` 로 먼저 보고, 아이폰 사파리처럼 재생 전 장면을 안 주면 소리 없이 잠깐 `play()` 해 깨운다.
  - 메인 배너(`railShot`)는 GIF·동영상 모두 첫 장면 그림을 쓴다(메인에 큰 원본을 걸지 않음).
  - 탈퇴·추방(`delete-account`·`admin-purge-user`)은 두 버킷의 내 폴더를 모두 지운다. 배포는 마이그레이션(버킷 생성)을 먼저, 함수를 나중에 한다(없는 버킷 목록 실패로 탈퇴가 멈추지 않게).
  - 남는 파일(저장 도중 이탈, 정리 실패) 정리는 #7 예약 작업에 debut-media 도 넣는다.
- **글 꼭지(#31, 2026-11-19 사용자 결정)**: `kind = 'text'` 칸. `note_kind`(intro·feeling·brag·free) 종류마다 1개(최대 4), 본문 1~600자, 제목 선택 1~40자(`char_length`, 화면은 코드 포인트로 같은 셈). 사진·GIF·동영상 20칸과 따로 센다(칸 자리 0~23).
  - 같은 `debut_photos` 표에 `position` 을 함께 써서 사진 사이에 섞인다. `debut_photos_shape` check 가 글 칸은 path 없음·본문 있음, 파일 칸은 글 열 없음을 지킨다.
  - `clean_gallery` 가 글의 줄바꿈을 \n 으로 맞추고 빈 줄을 하나까지 줄이고 앞뒤 공백·줄바꿈을 자른다(빈 제목은 없음). 파일 칸은 필요한 키만 남긴다.
  - `check_note` 가 글 하나를 본다: 종류·길이·30줄은 `invalid_note`, 보이지 않는 글자·방향 바꾸기 글자(본문 줄바꿈 제외)는 `note_hidden`, 금지어(`has_banned_word`, 제목+본문)는 `banned_word`. 오류의 detail 에 꼭지 종류를 실어 화면이 그 글을 연다. 종류 중복·5개 이상도 `invalid_note`.
  - `check_debut_notes(entry, items)` 는 저장 없이 글만 확인한다(주인·데뷔 확인 같음). 화면은 파일을 올리기 전에 부른다(막힐 글 때문에 큰 파일을 올렸다 지우지 않게).
  - `get_entry` gallery 는 글을 `{kind:'text', note_kind, title, body}` 로 순서대로 준다. `get_featured_at`(메인 배너)·인스타 이미지·흐르는 띠·표지는 글 칸을 뺀다.
  - 화면은 글을 React 텍스트로만 그린다(HTML 해석 없음).
- **읽기**: `get_entry` 가 `debut`(불리언)와 `gallery`(화보 사진)를 준다. `get_featured_at` 의 데뷔 `photos` 는 표를 모은 원래 사진만 싣는다. 화보 사진은 화보 상세에서만 보여 준다(메인 첫 화면 장수가 들쭉날쭉하지 않고, 투표 때 본 얼굴이 메인에 걸리게, #23). 내 글 목록(`my_entries`)도 `debut`(= `is_debut`)를 줘서 "화보 사진 올리기" 링크를 같은 판정으로 보여 준다(숨긴 1위 대신 이어받은 2위에 붙는다). 글이 숨겨지면 `get_entry` 가 null 이라 화보도 같이 안 보이고, 신고·숨김·삭제는 글 단위 규칙을 그대로 따른다.
- **화면**: 데뷔 글이면 `DetailPage` 가 `features/debut/DebutDetail` 로 넘긴다(숨긴 글은 주인에게 일반 상세). 꽃가루·흐르는 띠는 CSS 애니메이션만 쓰고, `prefers-reduced-motion` 이면 모두 끈다.
- **패션 매거진 지면(#31, 2026-11-20 사용자 결정)**: `Magazine.tsx` 가 화보 칸·글 꼭지를 패션지 웹 화보처럼 위에서 아래로 그린다(처음 만든 좌우로 넘기는 잡지 한 권은 버림, 결정기록). 지면 짜기는 순수 함수 `magazinePages.ts`(`buildPages`·`parasOf`, Vitest)가 맡는다: 표지 → 사진 지면(한 장·두 장 번갈아)·글 꼭지(자르지 않고 한 지면, 짧은 글은 뒤 사진 한 장과 함께) → 맺음. 쪽 번호·차례·넘김 단추·스크롤 틀이 없어 스크립트는 사진 등장·GIF 원본 받기·동영상 재생(IntersectionObserver)과 크게 보기만 맡는다. 라이브러리는 쓰지 않는다. 주인은 `/<게시판>/<글>/gallery`(`GalleryPage`·`GalleryForm`)에서 올린다. 사진 줄이기(`processPhoto`)·오류 문구는 등록 폼과 같이 쓴다.

## 5. 보안·개인정보
- 모든 테이블 RLS 켬. 쓰기는 RPC로만(테이블 직접 insert·update 권한 없음). `service_role` 키는 Edge Function 비밀값에만.
- 비밀값: Supabase URL·anon 키(공개 가능), service_role, Gmail 앱 비밀번호(보내는 주소도 비밀값으로만), VAPID 개인 키, Turnstile 비밀 키 → `.env`(git 제외) / Cloudflare·Supabase 비밀값. 저장소엔 `.env.example`만.
- SNS 링크는 허용 도메인만(아무 사이트로 보내는 악용 방지), `rel="noopener noreferrer"`.
- 업로드는 Storage RLS로 회원의 `<내 사용자 번호>/` 폴더에만, WebP·2MB·폴더당 120개까지(#31 20칸으로 60 → 120). 덮어쓰기(update) 정책이 없어 항상 새 이름으로 올리고, 글에 붙은 파일은 지우지 못한다(지우고 같은 이름으로 다시 올려 픽 받은 사진을 바꿔치기하는 길을 막음). 화면에서 다시 그려 위치 정보 제거.
- 메일 주소는 알림 발송에만 쓰고 화면에 보이지 않음. 댓글 작성자는 닉네임만.
- 관리자 화면은 `profiles.is_admin`만, 모든 관리 동작은 RPC에서 다시 확인하고 `admin_actions`에 남긴다. 되돌릴 수 없는 동작(탈퇴·계정 정리)은 최근 10분 안 구글 로그인만 받는다(비밀번호 로그인 시각은 세지 않음).
- 신고는 글·댓글 모두 `report(target, id, reason)` RPC 하나로 받는다. 한 사람이 같은 대상을 두 번 신고할 수 없다.
- 응답 보안 헤더(#11, `next.config.ts`): CSP(스크립트·연결·이미지는 자기 주소와 Supabase 주소만, 프레임 금지), `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy`, 운영에서는 HSTS. Next 의 인라인 스크립트 때문에 `script-src 'unsafe-inline'` 은 남는다(nonce 는 모든 페이지를 동적으로 그려야 해서 보류). #3 Turnstile 을 붙일 때 `challenges.cloudflare.com` 을 더한다.
- 이용약관(`/terms`)·개인정보처리방침(`/privacy`)은 #16 초안이다. 모으는 항목(이 절)이 바뀌면 `app/privacy/page.tsx` 표도 같은 커밋에서 고친다.
- 방문자 키 쿠키 `pd_vid`(임의 UUID, 1년)는 섞기 순서와 이동률을 하루 한 번만 세는 데만 쓴다. 계정·개인정보와 잇지 않는다.
- 서버의 로그인 확인은 `getClaims()`(토큰 서명 확인)로 한다. 회원 표시는 토큰의 `app_metadata.providers`, 실제 한도는 DB `caller_is_member()`(auth.identities)가 정한다.
- 임시 저장은 브라우저 IndexedDB(사진 Blob)와 localStorage(글자)에만 둔다. 서버로 보내지 않고, 등록이 끝나거나 로그아웃하면 지운다.

## 6. 성능
- 게시판 목록: `(round_id, board, pick_count desc)`·`(round_id, board, created_at desc)` 인덱스, 24개씩 이어 불러오기.
- 사진: Storage 공개 URL + Cloudflare 캐시. 목록은 작은 썸네일(업로드 때 같이 만든 480px WebP).
- `get_featured()`: 요청 하나 안에서 한 번만 읽는다(React `cache`, `features/featured/server.ts`). 게시판·글 상세는 페이지 데이터와 같이 읽기 시작해(`void getFeatured()`) 위 띠가 왕복을 더 늘리지 않게 한다. 요청 사이 캐시(1분)는 아직 없다 — 읽기 쪽 부하가 보이면 쿠키 없는 클라이언트로 `unstable_cache` 를 붙인다.
- 브라우저의 supabase-js 는 픽·더 보기를 처음 누를 때 불러온다(#11). 첫 화면 JS 에 실리지 않는다.
